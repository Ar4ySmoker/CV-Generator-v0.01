# AGENTS.md — инструкция для AI-агентов

> Прочти этот файл целиком перед началом работы в `CV-Generator-v0.01/`.
> Детальная архитектура, модель данных и API — в `docs/ARCHITECTURE.md`.
> План развития — в `docs/ROADMAP.md`. Не дублируй их здесь — только правила и ключевые точки входа.

## Что это

Веб-приложение из четырёх частей:

1. **Генератор CV** — пользователь вводит опыт (или вакансию), LLM адаптирует текст
   под вакансию, сервер отдаёт готовый `.docx` (ATS-friendly). Шаблоны, цвет, импорт PDF/DOCX.
2. **Трекер откликов** — личный кабинет: рассылка CV и отслеживание от отклика до офера
   (воронка этапов, таймлайн, заметки, контакты, собеседования, сравнение оферов).
3. **Каталог и поиск вакансий** — глобальный каталог + живой поиск по источникам
   (hh.ru, Хабр Карьера, Remote OK, Работа России, Jooble) + Telegram-лента.
4. **Команды** — доска вакансий по компаниям, таймлайны участников, отзывы о
   собеседованиях, чат, роли (владелец/участник/ментор/ревьюер).

## Стек (обязательный, не отклоняться)

- **Next.js 16** (App Router, Turbopack) + **TypeScript strict** + **Tailwind CSS v4**
- **shadcn/ui** (style `radix-maia`, base `mist`) — см. правило ниже

- **docx** (npm) — генерация `.docx` на сервере

  подключает свой ключ; фолбэк — серверный `DEEPSEEK_API_KEY`)
- Деплой: **Vercel**; тесты: **Vitest**

## ⚠️ Жёсткие правила

- **Строгий TypeScript — никаких `any`.** Типизируй всё; сужения через type guards/zod.
- **Без комментариев в коде**, если явно не попросили. Код должен быть самодокументируемым.
- **shadcn/ui — только готовые компоненты.** Новые составные собирай из shadcn-примитивов,
  не пиши вёрстку с нуля. Добавление: `npx shadcn@latest add <name>`.
- **Валидация на границе** — все входные данные API валидируются zod-схемой до использования.
- **Проверка владельца (`userId`) в каждом API-роуте** — запись чужого пользователя не должна
  быть доступна по чужому `id`.
- Соблюдай существующие паттерны: смотри соседние файлы и `docs/ARCHITECTURE.md`, прежде чем
  вводить новый подход.

## Безопасность

- Секреты — только в env; не хардкодить, не коммитить, не логировать.
- API-ключи пользователей шифруются (`lib/encryption.ts`, AES-256-GCM) и маскируются в UI.
- Каждый роут: авторизация (`getUserId`/`auth`) → `connectDb()` → валидация → проверка владельца/прав.
- Режим «сгенерировать опыт» требует обязательного дисклеймера (`disclaimerAccepted`).
- Новые эндпоинты, работающие с чужими данными, обязаны проверять `userId` — это не опционально.

## Режимы генерации и формы

1. **С опытом** — адаптация реального опыта под вакансию.
2. **Без опыта (junior)** — честное CV из навыков/образования/проектов.
3. **Сгенерировать опыт** — LLM придумывает стаж (обязателен дисклеймер).

Мультишаг: личные данные → навыки → опыт (только «с опытом») → образование → проекты →
языки → вакансия → оформление (объём «произвольная/одна страница», шаблон, свой промт).
«Сгенерировать опыт» — только личные данные → вакансия → оформление. С сохранённым профилем
вместо визарда открывается быстрый режим (`QuickGenerate`). Профиль — «мастер-данные»:
одностраничный редактор, теги доменов у опыта/проектов (по ним идёт отбор релевантности).

## Как добавить/изменить функциональность

См. `docs/ARCHITECTURE.md`, раздел «Как что-то добавить/поменять». Кратко:

- **Новый шаг формы CV** — `lib/schemas.ts` → `components/form/steps/*` → `ALL_STEPS` (`cv-form.tsx`).
- **Новое поле отклика** — модель (`lib/models/application.ts`) → `applicationUpdateSchema`
  (`lib/api-schemas.ts`) → PATCH в `api/applications/[id]` → UI.
- **Новый источник вакансий** — `lib/vacancy-sources/<id>.ts` + регистрация в `index.ts` + `VALID_SOURCES`.
- **Новый LLM-провайдер** — `lib/providers.ts`.

## Известные нюансы (не наступи дважды)

- В Mongoose нельзя называть поле `model` — конфликт с методом документа (в `ApiKey` — `modelName`).
- `bullets` в форме опыта — массив объектов `{value}`: `useFieldArray` в этой версии
  react-hook-form не поддерживает массивы примитивов.
- Роут-защита — в `proxy.ts` (Next 16 депрекейтил `middleware.ts`).
- `next-auth` v5 нестабилен — используется `5.0.0-beta.x`.
- hh.ru может блокировать IP Vercel (403) — источник помечается «недоступен», не роняет поиск.
- Telegram-лента парсит HTML-превью `t.me/s/<channel>` — хрупко к смене вёрстки.
- Rate limit на `/api/generate` и `/api/vacancies/search` пока не реализован (см. ROADMAP).
